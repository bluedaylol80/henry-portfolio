사용자 요구를 제품 방향으로, 개발 우선순위를 실행으로 연결합니다.

문제 → 판단 → 행동 → 결과 순서로 씁니다. 각 장의 근거 링크에서 근거까지 볼 수 있습니다.

01

사용자 조사·지표

  • 만족도 조사에서 예전 웹뷰 이벤트의 복귀 요구가 나왔다
  • 소프트런칭에서 상품 구성·재화 소비·초반 이탈을 확인했다

02

제품 판단

  • 인게임 미니게임을 먼저 적용하고 웹뷰로 확장하기로 했다
  • 상품·재화·초반 동선을 출시 전 개선 과제로 정리했다

03

개발 우선순위

  • 퍼블리셔 정책과 API 문서를 기준으로 다시 정의했다
  • 사례 — 소프트런칭 지표 → 개선 과제

04

실행·출시

  • 꾸미기 이벤트 기획서를 쓰고 AI로 프로토타입을 만들었다
  • 구매·쿠폰·서버 선택 UI/플로우 기획을 쓰고 협의했다

05

라이브 운영·표준화

  • 성과 — 카오스크로니클 종료 운영
  • 성과 — SKU 자동화·어뷰징 SOP
